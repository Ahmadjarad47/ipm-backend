## 1. الهدف
أنواع عناصر العمل (ميزة، مهمة، خطأ…) وحقولها المخصصة، وقواعد من يقدر يكون ابن مين (التسلسل الهرمي)، وأنواع الروابط بين العناصر (يحجب، مرتبط بـ…).
هي **إعدادات يديرها المدير بدون تعديل كود**، والأجزاء الجاية بتقرا منها: الجزء 03 بيربط كل نوع بسير عمل، 04 بيحدد الأنواع المسموحة بالمشروع، 05 بيفرض هالقواعد على العناصر والروابط.
ما في عناصر عمل ولا مشاريع بهالجزء، فبعض الحمايات (مثلاً «نوع مستخدم بعناصر») بتنضاف مع الجزء اللي بيعرّف الجدول المعني (انظر §9).

## 2. الجداول (schema `config`)
| الجدول | الأعمدة | القيود |
|---|---|---|
| `work_item_types` | `id`، `key`، `name`، `description`، `color`، `icon`، `sort_order`، `is_active`، **`fields jsonb`** (تعريفات الحقول المخصصة)، **`allowed_child_type_ids uuid[]`** + الأختام + `xmin` | `key` فريد بدون حساسية حالة وثابت: `^[a-z][a-z0-9_]{1,30}$`؛ `name` 1–100، `description` ≤300؛ `color` بصيغة `#RRGGBB` (CHECK)؛ `icon` من `feature task bug subtask milestone epic story` (CHECK)؛ `sort_order ≥ 0` |
| `relation_types` | `id`، `key`، `name`، `inverse_name`، `is_directed`، `is_acyclic`، `is_active`، **`allowed_pairs jsonb`** (`[{sourceTypeId, targetTypeId}]`، فاضي = أي نوع) + الأختام + `xmin` | `key` فريد بدون حساسية حالة: `^[a-z][a-z0-9_]{1,30}$`؛ `name` و`inverse_name` 1–60؛ غير الموجّه: `inverse_name = name` (CHECK) |

- **تعريف الحقل المخصص** (عنصر بمصفوفة `fields`): `key` (`^[a-z][a-z0-9_]{0,40}$`، فريد داخل النوع)، `label` (1–100)، `type` (`text number date boolean select user`)،
  `required`، `options[{value,label}]` (لـ `select` فقط: خيار واحد على الأقل وقيمهم فريدة)، `min`/`max` (للأرقام، `min ≤ max`)، `hint` (≤200)، `showInList`، `showOnCard`، `order` (≥0).
  الحقول مصفوفة داخل النوع (مش جدول) لأنها ما بتنقرأ إلا مع النوع، وهيك تعديلها بيغيّر `xmin` للنوع وبيظهر كامل بـ `audit_log` (نفس منطق صلاحيات الدور).
- **قواعد التسلسل الهرمي** (`allowed_child_type_ids`) عمود بنفس النوع الأب: كل نوع بيقول مين بيسمح يكون ابنه (ممكن نفسه، مثلاً مهمة داخل مهمة). الأنواع ما بتنحذف أبداً (R4) فالمصفوفة ما بتصير يتيمة.
- **ما في جدول لسجل التعديل**: سجل تعديل الأنواع (FR-TYP-10) هو `audit_log` الموجود (قبل/بعد، المستخدم، الوقت)، وفي رابط `history` يقراه (§5).
- المعرّفات UUIDv7. الأعمدة المخصصة بتنكتب بـ snake_case، والـ enums نص kebab-case.

## 4. قواعد العمل
| # | القاعدة | الخطأ |
|---|---|---|
| R1 | مفتاح النوع فريد (بدون حساسية حالة) وبالصيغة المحددة، وما بيتغيّر بعد الإنشاء (يتغيّر الاسم بس، فالتاريخ ما بينكتب من جديد) | 409 `WorkItemType.KeyTaken`، 422 `WorkItemType.KeyImmutable` |
| R2 | لون النوع `#RRGGBB`، والأيقونة من القائمة المسموحة، والترتيب عدد صحيح ≥ 0 | 400 (حقل) |
| R3 | قواعد الحقل المخصص: مفتاح بالصيغة وفريد داخل النوع، تسمية مطلوبة، نوع مسموح، خيارات `select` ≥1 وفريدة، `min ≤ max`، حد أقصى **40 حقل** بالنوع | 400 `WorkItemType.InvalidFields` + الأخطاء مفصّلة بالحقل (`fields[2].key`…) |
| R4 | الأنواع **ما بتنحذف**، بتتعطّل بس (لأن عناصر وروابط رح تأشّر عليها) | — (ما في رابط حذف) |
| R5 | قواعد التسلسل: كل نوع بالقائمة موجود، بدون تكرار، ومسموح النوع نفسه | 400 `WorkItemType.ChildTypeNotFound` |
| R6 | مفتاح نوع الرابط فريد بدون حساسية حالة وبالصيغة المحددة، وثابت بعد الإنشاء | 409 `RelationType.KeyTaken`، 422 `RelationType.KeyImmutable` |
| R7 | نوع الرابط غير الموجّه اسمه العكسي = اسمه، وغير الموجّه ما بيمنع الحلقات (`is_acyclic` بس للموجّه) | 400 (حقل `inverseName` / `acyclic`) |
| R8 | أزواج الأنواع المسموحة لنوع الرابط لازم تأشّر على أنواع موجودة، والفاضي = أي نوع | 400 `RelationType.PairTypeNotFound` |
| R9 | `key` و`directed` و`acyclic` بتنقفل لما يصير في روابط فعلية مستعملة النوع، والتضييق على الأزواج بيتمنع إذا في رابط ما بيطابق | 422 `RelationType.LockedAfterUse` (**مقفلة لحد الجزء 05**، انظر §9) |
| R10 | تعطيل نوع الرابط بيمنع إنشاء روابط جديدة منه بس الموجودة بتضل (**بالجزء 05**) | — |
| R11 | تعطيل نوع عمل مستعمل كنوع افتراضي بمشروع، أو تغيير سير عمله بوجود عناصر بحالات ما بيدعمها: **بالأجزاء 03 و04 و05** | — |

## 5. الروابط (`/api/v1`، مجموعتان: «أنواع العمل»، «أنواع الروابط»)
| الرابط | الصلاحية | الطلب ← الرد | ملاحظات |
|---|---|---|---|
| `GET /work-item-types` | مسجّل | `?active=` ← مصفوفة بالنوع كامل (مع الحقول والأبناء) بترتيب `order` | بدون ترقيم (قائمة إعدادات قصيرة) |
| `GET /work-item-types/{id}` | مسجّل | ← النوع كامل | ETag |
| `POST /work-item-types` | `workitem.types.manage` | `{ key, name, description?, color, icon, order?, active? }` ← 201 | الحقول والأبناء فاضيين، R1 R2 |
| `PUT /work-item-types/{id}` | `workitem.types.manage` | `{ name, description, color, icon, order, active, key? }` | If-Match؛ `key` اختياري ومجرد فحص (R1) |
| `PUT /work-item-types/{id}/fields` | `workitem.fields.manage` | `{ fields: [...] }` (القائمة الكاملة) | If-Match، R3 |
| `PUT /work-item-types/{id}/children` | `workitem.types.manage` | `{ childTypeIds: [...] }` (القائمة الكاملة) | If-Match، R5 |
| `GET /hierarchy-rules` | مسجّل | ← `{ pairs: [{ parentTypeId, childTypeId }] }` | عرض مسطّح لكل الأنواع (الواجهة بتستعمله للمصفوفة) |
| `GET /work-item-types/{id}/history` | `workitem.types.manage` | ترقيم ← `[{ at, userId, userName, action, before, after }]` | من `audit_log`، الأحدث أولاً |
| `GET /relation-types` | مسجّل | `?active=` ← مصفوفة | |
| `GET /relation-types/{id}` | مسجّل | ← نوع الرابط | ETag |
| `POST /relation-types` | `workitem.relationtypes.manage` | `{ key, name, inverseName, directed, acyclic, active?, allowedPairs? }` ← 201 | R6 R7 R8 |
| `PUT /relation-types/{id}` | `workitem.relationtypes.manage` | `{ name, inverseName, directed, acyclic, active, allowedPairs, key? }` | If-Match، R6–R9 |
| `GET /relation-types/{id}/history` | `workitem.relationtypes.manage` | مثل سجل النوع | |

الأخطاء problem+json بالعربي بالصيغة المتفق عليها بالجزء 00 (400/403/404/409/412/422/428). أنواع الـ enums (`icon`، `type` الحقل) كلها kebab-case بالـ JSON.

## 6. البيانات الأولية
- **دايماً (idempotent، بتضيف الناقص حسب `key` وما بتلمس المعدّل):** الأنواع الخمسة من `seed.ts` بحقولها وقواعدها (ميزة، مهمة، خطأ، مهمة فرعية، معلم رئيسي)،
  وقواعد التسلسل (ميزة←مهمة/خطأ، مهمة←مهمة فرعية/خطأ، خطأ←مهمة فرعية، معلم←ميزة)، وأنواع الروابط الثلاثة (`blocks` موجّه ويمنع الحلقات، `relates` غير موجّه، `duplicates` موجّه ويمنع الحلقات).
  السبب: ما بيشتغل مشروع بدون أنواع، وهي إعدادات افتراضية يعدّلها المدير.
- **بالتطوير فقط:** ما في شي إضافي.

## 7. سيناريوهات القبول
1. أي مستخدم مسجّل بيقرا الأنواع الخمسة وأنواع الروابط الثلاثة والتسلسل الهرمي، بترتيب `order`، وكل نوع معه حقوله وأبناؤه المسموحين. بدون توكن ← 401.
2. موظف عادي (`staff`) بيحاول `POST /work-item-types` أو `/relation-types` ← 403، ومدير النظام بينجح (201 مع ETag).
3. مستخدم معه `workitem.fields.manage` بس: بيعدّل الحقول (200) لكن `PUT /work-item-types/{id}` ← 403؛ والعكس لمن معه `workitem.types.manage` بس.
4. R1: مفتاح مكرر (حتى بحروف كبيرة) ← 409؛ مفتاح بصيغة غلط ← 400؛ إرسال `key` مختلف عند التعديل ← 422.
5. R2: لون أو أيقونة غير صالحين ← 400 بحقل عربي.
6. R3: حقل بمفتاح مكرر، `select` بدون خيارات أو بقيم مكررة، `min > max`، أكثر من 40 حقل ← 400 بالمسار الدقيق (`fields[1].options`)؛ حفظ صالح ← 200 وETag جديد.
7. R4: ما في `DELETE` على الأنواع (405)؛ التعطيل بـ `active=false` بيشتغل، والنوع المعطّل بيبقى بالقراءة.
8. R5: ابن مجهول ← 400؛ التسلسل بعد التعديل ظاهر بـ `GET /hierarchy-rules`، ونوع يقدر يكون أب لنفسه.
9. R6–R8 على أنواع الروابط: مفتاح مكرر، غير موجّه باسم عكسي مختلف، غير موجّه بـ `acyclic=true`، زوج بنوع مجهول ← الأخطاء المكتوبة.
10. تعديل نوع أو نوع رابط بـ ETag قديم ← 412، وبدون `If-Match` ← 428.
11. كل تعديل (حقل، ابن، تفعيل) بيظهر بـ `audit_log` مع `user_id` الحقيقي، و`GET .../history` بيرجّعه مرتب والأحدث أولاً (وممنوع على من ما معه الصلاحية).
12. `dotnet test` ناجح، الروابط ظاهرة بـ `/docs` تحت «أنواع العمل» و«أنواع الروابط»، و`docs/http/02-work-item-types.http` فيه مثال لكل رابط.

## 8. قرارات
**حسمها صاحب المشروع (الخارطة):** إعدادات الأنواع بترتيب الأجزاء: 02 بعد الهوية وقبل سير العمل (03).

**أخدتها أنا (صحّحني إذا لازم):**
- **ربط النوع بسير العمل مش بهالجزء.** النوع بالواجهة عنده `workflowId`، لكن جدول سير العمل بيجي بالجزء 03؛ فبيضيف الجزء 03 عمود `workflow_id` للأنواع (مع seed يربط الأنواع الخمسة) ويطلبه عند الإنشاء. هيك ما منعمل مفتاح أجنبي لجدول لسا مش موجود.
- **القراءة مفتوحة لأي مستخدم مسجّل** (متل الـ mock)، لأن الواجهة بتحتاجها بكل شاشة. صلاحيات العرض (`workitem.types.view`، `workitem.relations.view`) بتنفرض على بيانات العناصر والروابط بالجزء 05 مش على الإعدادات.
- **الحقول المخصصة والأبناء أعمدة داخل النوع** (jsonb و`uuid[]`) مش جداول، حتى يعدّل ETag النوع ويظهر كامل بسجل التدقيق.
- **ما في `PUT /hierarchy-rules` (استبدال المصفوفة كلها)** متل الـ mock، لأنه تعديل بدون `If-Match` يكتب فوق تعديلات غيرك. بداله تعديل أبناء كل نوع بـ `If-Match` (`PUT /work-item-types/{id}/children`) ويضل `GET /hierarchy-rules` للعرض المسطّح. الواجهة بتحتاج تعديل بسيط لما ننتقل للـ API الحقيقي (خارج شغلنا).
- **سجل تعديل الأنواع من `audit_log`** بدون جدول خاص ولا نصوص عربية مولّدة للفروقات؛ الواجهة هي اللي بتصيغ فرق «قبل/بعد» (أو بيصير بالجزء 08 مع واجهة التدقيق).
- **حد أقصى 40 حقل لكل نوع** حتى ما يكبر الـ jsonb وشاشة الإنشاء بدون سقف.
- **أيقونات النوع من قائمة ثابتة بالكود** (نفس 7 أسماء الواجهة)، مش نص حر.
- **الأنواع الافتراضية دايماً بالـ seed** (مش تطوير فقط) لأن النظام بدونها ما بيشتغل.
- **التفعيل/التعطيل ضمن `PUT`** (حقل `active`) مش رابط مستقل، لأنه حقل عادي بالنوع بدون قواعد خاصة لسا.

## 11. تعديلات أثناء التنفيذ
غيّرتها أثناء المراحل 1–4 بدون ما تغيّر الاتفاق، وكلها موثّقة هون:
1. **مفتاح النوع ونوع الرابط بيقبلوا حروفاً كبيرة** وبيتحوّلوا لأحرف صغيرة قبل الفحص والحفظ؛ هيك `BUG` و`bug` نفس المفتاح (409 عند التكرار) والفهرس الفريد العادي كافي. صيغة المفتاح الخاطئ بترجّع 400 بالرمز `WorkItemType.KeyInvalid` / `RelationType.KeyInvalid`.
2. **`order` و`active` بالتعديل اختياريين**: إذا انحذفوا من جسم `PUT` بيضلوا بقيمتهم الحالية (حتى ما ينعطّل نوع بالغلط لأن حقل نُسي). نفس الشي لـ `active` بنوع الرابط. عند الإنشاء الافتراضي `order = 0` و`active = true`.
3. **أخطاء الحقول المخصصة بمسارها الدقيق** (`fields[1].key`، `fields[2].options`، `fields[4].max`، و`fields` لتجاوز 40) داخل `errors` بصيغة problem+json؛ القواعد معرّفة مرة وحدة بالـ domain (`FieldDefinitions.Validate`) ومستعملة بالفاليديتر وبالكيان.
4. **أيقونة غير معروفة** (مثلاً `rocket`) بتنرفض عند قراءة الجسم برمز `Request.Malformed` (400) لأنها قيمة enum؛ اللون والترتيب بيرجعوا خطأ عربي على الحقل.
5. **غير الموجّه** بنوع الرابط: خطأ الاسم العكسي `RelationType.InverseNameMustMatch` وخطأ منع الحلقات `RelationType.AcyclicNeedsDirected` (400)، ومعهم قيدين CHECK بالقاعدة.
6. **`DELETE` على الأنواع بيرجّع 405** (ما في رابط حذف أصلاً، R4).
7. **سجل التعديل** (`history`): `action` بيرجع `insert` أو `update` أو `delete`، و`before`/`after` كائن JSON (عند `update` الأعمدة المتغيّرة فقط)، و`userName` اسم المستخدم من جدول المستخدمين. جاء من واجهة جديدة `IAuditLogReader` بطبقة التطبيق (بتنفّذها البنية التحتية) لتستعملها شاشة التدقيق بالجزء 08.
8. **الـ seed** بمعرّفات ثابتة (`…-8003-…` للأنواع و`…-8004-…` لأنواع الروابط) وبيضيف الناقص حسب `key` ما بيلمس اللي عدّله المدير. أبناء النوع بينزرعوا فقط عند إنشاء النوع.
