# الجزء 11: إشعارات تلغرام — المواصفة

> المرحلة 0 من [خط الإنتاج](../MODULE-PIPELINE.md). الحالة: **قيد التنفيذ**.
> يعتمد على: [الجزء 08](08-activity-audit-notifications.md) (مُسلَّم): `NotificationEmitter` وجدول `activity.notifications`. وهو الجزء اللي أجّلناه هناك بعنوان «Outbox + قناة ثانية».
> المرجع (للفهم فقط): Telegram Bot API (`sendMessage`، `getUpdates`، `setWebhook`، `deleteWebhook`) وحدودها: حوالي 30 رسالة/ثانية للبوت كله، ورسالة/ثانية للمحادثة الواحدة، و`429` مع `retry_after`.

## 1. الهدف
الفريق بدّه إشعارات المهام على تلغرام مش بس داخل التطبيق. الحسابات ما بتنعمل من مدير، فما في طريقة نجمع معرّف تلغرام وقت الإنشاء، والبوت **ما بيقدر يراسل حدا ما ضغط Start**، وبدّه `chat_id` الرقمي مش `@username`. فكل مستخدم بيربط تلغرام بنفسه من ملفه الشخصي برابط عميق بيستعمل مرة وحدة. بعد الربط، كل إشعار من الأنواع المحدّدة (النسخة الأولى: **تكليفك بعنصر عمل**) بيدخل جدول صادر (Outbox) ويرسله عامل خلفي بيحترم حدود تلغرام، فما بتنسدّ الطوابير بالدفعات ولا بيضيع شي لو تلغرام وقع.

**مش ضمن هالجزء:** انظر §10.

## 2. الجداول
**`activity.telegram_links`** (كيان مدقَّق `AuditableEntity`: ربط حساب = تغيير أمني):
| العمود | ملاحظات |
|---|---|
| `id` (uuid v7) · `user_id` | فريد: مستخدم واحد = ربط واحد |
| `chat_id` (`bigint`) | فهرس. محادثة تلغرام الخاصة. لو محادثة مربوطة بمستخدم تاني بتنتقل (بتنحذف القديمة) |
| `telegram_username` (≤64, اختياري) | للعرض فقط |
| `linked_at` · `disabled_at?` | `disabled_at` بيتعبّى لما البوت ينحظر (403) |
| الأعمدة المدقَّقة | `created_at`، `created_by`، `updated_at`، `updated_by`، `xmin` (النسخة) |

**`activity.telegram_outbox`** (سجل عادي مثل `notifications`، مش مدقَّق):
| العمود | ملاحظات |
|---|---|
| `id` (uuid v7) | |
| `notification_id` | **فريد**: رسالة وحدة لكل إشعار (عدم التكرار) |
| `user_id` · `chat_id` | |
| `text` (≤4096) | HTML جاهز (النص كله مهروب) |
| `status` | `pending` / `sent` / `failed` / `expired` (نص kebab) |
| `attempts` · `next_attempt_at` · `last_error?` | `last_error` ≤500 وبدون أي توكن |
| `created_at` · `sent_at?` | فهرس `(status, next_attempt_at)` |

رمز الربط (Link token) **مش بقاعدة البيانات**: Redis، المفتاح `telegram:link:<SHA-256(token)>` والقيمة معرّف المستخدم، TTL **10 دقائق**، ومفتاح ثاني `telegram:link-user:<userId>` بيحمل مفتاح الرمز الحالي ليبطل الرمز السابق عند إصدار جديد.

## 3. الصلاحيات
**ما بتنضاف مفاتيح** (تبقى 42). كل شي على بيانات المستخدم نفسه (مصادَق بدون صلاحية). رابط الـ webhook بدون تسجيل دخول: الترويسة السرية هي الاعتماد.

## 4. قواعد العمل
| # | القاعدة | الخطأ |
|---|---|---|
| R1 | **الإعداد:** القسم `Telegram` (`Enabled`، `BotToken`، `BotUsername`، `Mode` = `Polling` أو `Webhook`، `WebhookUrl`، `WebhookSecret`، `AppBaseUrl`، `MessagesPerSecond` = 25). الميزة مفعّلة فقط إذا `Enabled` و`BotToken` غير فاضي. غير هيك: ما في خدمات خلفية، والتطبيق بيشتغل مثل قبل، ورابط الربط بيرجّع خطأ عربي واضح. تفعيل بدون توكن **ما بيوقّع** الإقلاع (بينزل لمعطّل) | 422 `Telegram.Disabled` |
| R2 | **بدء الربط:** `POST /telegram/link` بيصدر رمزاً عشوائياً (32 بايت base64url، يناسب `start` بحد 64 حرف) ويرجّع `deepLink = https://t.me/<bot>?start=<token>` و`expiresAt`. إصدار رمز جديد **بيبطل** رمز المستخدم السابق | 422 |
| R3 | **إتمام الربط:** المستخدم بيضغط Start فبيوصل البوت `/start <token>` بمحادثة **خاصة** (غير الخاصة تُتجاهل). الرمز بيُستهلك مرة وحدة (حذفه عند القراءة). صالح ← ينشأ ربط أو يُعاد ربطه (`Relink`) بالمحادثة الجديدة، والبوت بيردّ «تم ربط حسابك ✅». رمز منتهٍ أو مستخدم أو خاطئ، أو `/start` بلا رمز ← رد تعليمات (افتح ملفك الشخصي واضغط «اربط تلغرام») ولا يُغيَّر شي | — |
| R4 | **فك الربط:** `DELETE /telegram/link` (idempotent، 204 حتى لو ما في ربط) وأمر `/stop` بالبوت (بيردّ تأكيداً). بعد الفك ما بيدخل صادر جديد لهالمستخدم؛ الرسائل المعلّقة بتبقى وتفشل بشكل طبيعي عند الإرسال إن صار الربط معطّلاً (R9) | — |
| R5 | **قراءة الحالة:** `GET /telegram/link` ← `{ enabled, botUsername, linked, telegramUsername, linkedAt }`. `linked = false` إذا الربط غير موجود أو معطّل (`disabled_at`) | — |
| R6 | **الصادر (Outbox):** `NotificationEmitter.EmitAsync` — بعد إنشاء `Notification` بنفس الفلاتر (مستلم فعّال، بيشوف المشروع، مش الفاعل) — إذا نوعه ضمن `NotificationKinds.TelegramDefault` (النسخة الأولى: `work-item.assigned`) والمستلم عنده ربط فعّال، بيضيف `TelegramMessage` **بنفس `SaveChanges`** (transactional outbox). الروابط تُجلب دفعة وحدة لكل استدعاء | — |
| R7 | **صيغة الرسالة:** HTML (`parse_mode=HTML`، بدون معاينة روابط): عنوان بخط عريض ثم النص ثم سطر رابط `AppBaseUrl + link`. **كل نص مستخدم بيُهرَّب** (`& < >`). زر Inline بالرابط **بس لو `AppBaseUrl` بـ https** (تلغرام بيرفض localhost بالأزرار)، وإلا بيبقى الرابط نصاً | — |
| R8 | **حدود الإرسال:** سقف عام `MessagesPerSecond` (Token bucket، الافتراضي 25) أقل من حد تلغرام، وفاصل **≥ 1 ثانية** للمحادثة الواحدة (بإعادة جدولة الصف مش بالانتظار)، وعامل واحد بيطالب بالصفوف المستحقة بـ `FOR UPDATE SKIP LOCKED` (آمن لو تعدّد النسخ) | — |
| R9 | **نتائج الإرسال:** نجاح ← `sent`. `429` ← إعادة جدولة بـ `retry_after` (بدون احتساب فشل). `403` أو `400 chat not found` (Blocked) ← `failed` ويُعطَّل الربط (`disabled_at`). خطأ مؤقت (5xx/شبكة/مهلة) ← إعادة محاولة بتأخير أسي **5ث·2ⁿ بسقف 10 دقائق**، **حد أقصى 8 محاولات** ثم `failed`. أي 4xx تاني ← `failed` مباشرة. معلّق أكثر من **24 ساعة** ← `expired` | — |
| R10 | **الاستقبال:** `Mode=Polling` (للتطوير، بلا عنوان عام): `deleteWebhook` مرة ثم `getUpdates` طويل (25ث، `allowed_updates=["message"]`، تتبّع `offset`). `Mode=Webhook` (الإنتاج): `setWebhook(url, secret_token, allowed_updates)` عند الإقلاع، و`POST /telegram/webhook` بدون تسجيل دخول يتحقق من ترويسة `X-Telegram-Bot-Api-Secret-Token` بمقارنة **ثابتة الزمن** (خطأ ← 401)، حد الجسم 64 كيلوبايت (أكثر ← 413)، وبيرجّع **200 دايماً** للتحديثات المقبولة (حتى لو ما فهمها) كي ما يعيد تلغرام الإرسال | 401 / 413 |
| R11 | **السرية:** التوكن بالرابط (`/bot<token>/…`) فعميل HTTP الخاص بتلغرام بدون أي logging (`RemoveAllLoggers`)، والسجلات ما بتحتوي توكن ولا نص رسائل ولا رموز ربط. ملف `.env` خارج git و`.env.example` فاضي القيم | — |
| R12 | **الإشعار الداخلي ما بيتأثر:** فشل تلغرام ما بيفشّل الطلب ولا بيمسّ إشعار التطبيق/SignalR؛ الإرسال بالخلفية بعد الـ commit | — |

| `GET /telegram/link` | مصادَق | ← `{ enabled, botUsername, linked, telegramUsername, linkedAt }` | R5 |

## 6. البيانات الأولية
لا شي. الميزة معطّلة افتراضياً (`Telegram:Enabled=false`). `docker-compose.yml` بيفعّلها بوضع `Polling` وبيقرأ التوكن واسم البوت من `.env` عبر `TELEGRAM_BOT_TOKEN` و`TELEGRAM_BOT_USERNAME`.

## 7. سيناريوهات القبول
1. **الربط (R2–R3):** إصدار رمز ← `deepLink` صحيح؛ webhook بـ `/start <token>` من محادثة خاصة ← `GET /telegram/link` يرجّع `linked: true` واسم المستخدم.
2. **رمز لا يصلح (R3):** إعادة استعمال نفس الرمز، أو رمز منتهٍ/خاطئ، أو رمز سابق أُبطل بإصدار جديد ← ما في ربط ورد تعليمات.
3. **أمان الـ webhook (R10):** ترويسة سرّية خاطئة أو ناقصة ← 401؛ جسم أكبر من 64 كيلوبايت ← 413.
4. **الصادر (R6):** تكليف عنصر لمستخدم مربوط ← صف واحد بـ `pending`؛ الفاعل المكلَّف لنفسه ما بيستلم؛ مستخدم غير مربوط ما بيستلم؛ نوع خارج المجموعة (تغيّر حالة) ما بيدخل.
5. **الإرسال (R8–R9):** تشغيل العامل ← `sent` والنص مهروب HTML؛ `429` ← الصف ما زال `pending` و`next_attempt_at` بعد `retry_after`؛ `403` ← `failed` والربط معطّل (`linked: false`)؛ فشل مؤقت ← `attempts` يزيد والتأخير أسي؛ 8 محاولات ← `failed`.
6. **فك الربط (R4):** `DELETE` ← 204، ومرة ثانية 204، وتكليف جديد بعدها ما بيضيف صف.
7. **تعطيل الميزة (R1):** `Telegram:Enabled=false` ← `GET` يرجّع `enabled: false`، `POST` ← 422 `Telegram.Disabled`، ولا خدمات خلفية.
8. **التوافق:** كل اختبارات 00–10 بتضل خضراء، و`MigrationTests` ناجح.

## 8. قرارات
- **Outbox بنفس الـ `SaveChanges`:** بيضمن إن كل إشعار مؤهّل بيوصل ولو وقع التطبيق أو تلغرام بعد الـ commit (عكس إشعارات 08 اللي بعد الـ commit). الكلفة جدول إضافي وعامل. **البديل:** إرسال مباشر بعد الـ commit (أبسط، بس بيضيع عند الفشل ولا بيحترم الحدود). *مقترحي: Outbox.*
- **بدون مكتبة تلغرام:** عميل `HttpClient` صغير (4 استدعاءات) بدل تبعية كبيرة، مع تحكم كامل بالتصنيف وبعدم تسريب التوكن.
- **Polling للتطوير وWebhook للإنتاج:** مفتاح واحد `Telegram:Mode` ومسار معالجة واحد (`ProcessTelegramUpdate`).
- **رموز الربط بـ Redis مش بقاعدة البيانات:** قصيرة العمر ومفتاحها SHA-256 (حتى تسريب Redis ما بيكشف الرمز الخام).
- **التكليف فقط بالنسخة الأولى:** المجموعة `TelegramDefault` سهلة التوسعة (`approval.requested`، `comment.mentioned`).
- **بدون تفضيلات لكل مستخدم** (بس ربط/فك ربط).
