## 1. الهدف
ربط مستودعات Git (Gitea وGitHub وGitLab) بالمشروع حتى يظهر شغل المطوّرين على عناصر العمل: كل commit أو branch أو Pull Request فيه رمز عنصر (`ERP-104`) بيرتبط بالعنصر تلقائياً، وبيطلع على العنصر مؤشر التطوير (إيداعات، PR مفتوحة، PR مدموجة).
وبيشمل: ربط المستودع وفصله، استقبال الـ webhooks بتوقيع وحماية من التكرار وإعادة الإرسال، سجل التسليمات وإعادة معالجة الفاشل، المزامنة اليدوية من خادم Git، نمط رمز العنصر لكل مشروع، والربط اليدوي.
**الدمج في Git لا ينقل العنصر ولا يعتمده أبداً** (FR-GIT-08): بس بيسجّل الحدث.

## 2. الجداول
| الجدول (schema) | الأعمدة | القيود |
|---|---|---|
| `git.repositories` | `id`، `project_id`، `provider` (`gitea`/`github`/`gitlab`)، `name` (`owner/repo`)، `url`، `default_branch`، `is_connected`، **`access_token_cipher`** و**`webhook_secret_cipher`** (مشفّران)، `last_sync_at`، `last_sync_error` + الأختام + `xmin` | `(project_id, name)` فريد للمتصل؛ FK للمشروع؛ **السرّان `ExcludeFromAudit` وما بيرجعوا بأي رد**؛ الفصل بيمسح السرّين ويبقي السجل |
| `git.git_events` | `id`، `project_id`، `repository_id`، `kind` (`push`/`pull-request`/`merge`)، `title`، `branch`، `sha` (40)، `author`، `url`، **`work_item_refs text[]`**، **`manual_refs text[]`**، `pr_number`، `pr_state` (`open`/`merged`/`closed`)، `delivery_id` + الأختام | فريد `(repository_id, sha)` للـ push وفريد `(repository_id, pr_number)` للـ PR؛ GIN على `work_item_refs`؛ فهرس `(project_id, created_at)` |
| `git.webhook_deliveries` | `id`، `project_id`، `repository_id`، `provider`، `delivery_id`، `event`، `signature_valid`، `outcome` (`processed`/`duplicate`/`rejected`/`failed`)، `message`، `linked_refs text[]`، `payload` (نص خام، **للفاشل فقط**) + `created_at` | فريد جزئي `(repository_id, delivery_id)` للمعالَج والفاشل (المرفوض والمكرر ما بيحرقوا المعرّف)؛ فهرس `(project_id, created_at)` |
| `projects.projects` (عمود) | **`ref_pattern`** نص اختياري (≤100) | يحرّك ETag المشروع ويظهر بالتدقيق؛ الافتراضي مشتق من الرمز |

- **التشفير:** السرّان بيتشفّروا بـ AES-GCM بمفتاح من الإعداد `Git:SecretKey` (32 بايت base64). مفتاح ثابت بالتطوير والاختبار، وبالإنتاج **لازم يُضبط وإلا ما يقلع** النظام. الخطأ بالمفتاح ما بيطبع السرّ.
- العناصر `ExcludeFromAudit` للأسرار؛ بقية الأعمدة بتتدقّق.

## 3. الصلاحيات
الفحص بالمعالج (بالمشروع): مشروع غير مرئي ← **404**، مرئي بدون الصلاحية ← **403** (ويتسجّل `permission-denied`).
| الصلاحية | نطاقها | بتفتح |
|---|---|---|
| `git.view` | مشروع | قراءة المستودعات والأحداث وسجل التسليمات ومؤشر التطوير |
| `git.manage` | مشروع | ربط وفصل المستودع، تدوير السرّ، نمط الرمز، إعادة معالجة تسليم فاشل |
| `git.sync` | مشروع | المزامنة اليدوية |
| `tasks.edit` | مشروع | ربط وفك ربط commit بعنصر يدوياً |
| **بدون صلاحية** | — | `POST /webhooks/{provider}/{repoId}` عام، ومحميّ بالتوقيع فقط |

## 4. قواعد العمل
| # | القاعدة | الخطأ |
|---|---|---|
| R1 | **ربط مستودع** (`POST /projects/{id}/repositories`): المزوّد مدعوم، `name` بصيغة `owner/repo`، الرابط **https** عام (بدون بيانات دخول بالرابط، بدون منفذ، بدون `localhost` أو عناوين خاصة أو IPv6 محلي أو IPv4-mapped، حماية SSRF)، الفرع الافتراضي والتوكن مطلوبان، سرّ الـ webhook ≥ 16 حرفاً وإذا غاب بيتولّد 32 بايت عشوائي. المشروع غير مؤرشف. المستودع المتصل بنفس الاسم بالمشروع ← 409. **بيرجع `webhookUrl` والسرّ المُولَّد مرة وحدة** | 400 (حقول) / 409 `Git.AlreadyConnected` / 422 مشروع مؤرشف |
| R2 | **فصل** (`.../disconnect`): `is_connected = false` وبيمسح التوكن والسرّ، وسجل الأحداث والتسليمات بيضل (FR-GIT-09). المستودع المفصول ما بيستقبل تسليمات (التوقيع بيفشل) ولا بينزامن | — |
| R3 | **تدوير السرّ** (`.../rotate-secret`): للمتصل فقط، بيولّد جديداً ويرجّعه **مرة وحدة**، والتدقيق بيسجّل التدوير بدون القيمة (NFR-04) | 422 مفصول |
| R4 | **نمط الرمز** (`PUT /projects/{id}/ref-pattern`، If-Match، `git.manage`): فاضي/null = الافتراضي `\b(<CODE>-\d+)\b`. النمط ≤100 حرف، **مجموعة التقاط واحدة بالضبط**، **بدون مراجع خلفية ولا تطلّع أمامي/خلفي** (بيتنفّذ بمحرّك `NonBacktracking` ومهلة، فما في ReDoS)، ولازم يلتقط رموز عناصر المشروع الحقيقية (حتى 5) بأي شكل شائع (`ERP-104` و`[ERP-104]` و`feature/ERP-104`…) | 422 `Git.RefPatternInvalid` |
| R5 | **الاستقبال** (`POST /webhooks/{provider}/{repoId}`، عام): المستودع موجود (404)؛ ترويسة معرّف التسليم والطابع الزمني **إلزاميان** (400)؛ التوقيع على المادة `"<timestamp>.<rawBody>"` بـ HMAC‑SHA256 بسرّ المستودع، بمقارنة ثابتة الزمن: **Gitea** `X-Gitea-Signature`، **GitHub** `X-Hub-Signature-256` (`sha256=…`)، **GitLab** `X-Gitlab-Token` = السرّ نفسه. الطابع بتاريخ ISO أو ثوانٍ/ميلي ثانية، وخارج ±5 دقائق ← مرفوض (حماية إعادة الإرسال). كل رفض بيتسجّل بسجل التسليمات (`rejected`) بدون ما يحرق معرّف التسليم | 400 / 401 `Git.InvalidSignature` / 401 `Git.StaleDelivery` |
| R6 | **عدم التكرار:** نفس `(repository, deliveryId)` سبق معالجته أو فشل ← يرجع 200 `outcome = duplicate` بدون معالجة. الحد الأقصى للجسم 1 ميغابايت (413) | 413 |
| R7 | **المعالجة:** `push`: كل commit بيتخزّن مرة (فريد بالـ sha)، والرموز من الرسالة **والفرع**؛ `pull_request` (والاسم عند GitLab `Merge Request Hook`): الرموز من العنوان وفرع الرأس، بيتحدّث الحدث بنفس الرقم (فتح، إغلاق، دمج) **ويحتفظ بالروابط اليدوية**، والحالة `open` أو `closed` أو `merged`. مسح أول 2000 حرف فقط من كل نص. **بتنربط فقط الرموز اللي إلها عنصر موجود بنفس مشروع المستودع**. الفشل (جسم غير JSON، حدث فاسد) بيتسجّل `failed` مع الجسم الخام للإعادة | — |
| R8 | **الدمج لا يغيّر العنصر (FR-GIT-08):** دمج PR ما بينقل حالة العنصر ولا بيعتمد ولا بيستهلك موافقة؛ بس بيسجّل الحدث (والإشعار للمكلّفين بالجزء 08) | — |
| R9 | **سجل التسليمات** (`GET /git/deliveries?projectId=`، `git.view`): مشروع واحد إلزامي، بترقيم، الأحدث أولاً، بدون الجسم الخام. **إعادة المعالجة** (`POST /git/deliveries/{id}/redeliver`، `git.manage`): للفاشل فقط، على الجسم المخزّن، فإذا نجحت صارت `processed` (والجسم بيتمسح) وإلا بتضل `failed` برسالة الخطأ | 422 `Git.NotRedeliverable` |
| R10 | **المزامنة** (`POST /projects/{id}/git-sync` `{ repositoryId }`، `git.sync`): تجيب آخر 50 commit من الفرع الافتراضي عبر **واجهة مزوّد Git** (توكن المستودع، مهلة 10 ثوانٍ، نفس حماية SSRF)، وتمرّرهم بنفس مسار الـ push (idempotent بالـ sha). بتسجّل `last_sync_at`/`last_sync_error` وتدقّق الأعداد (على الخادم، الجديدة، العناصر المرتبطة). مستودع مفصول ← 422، تعذّر الاتصال أو المهلة ← 502 مع `last_sync_error` | 422 / 502 `Git.SyncFailed` |
| R11 | **الربط اليدوي:** `POST /git-events/{id}/link` `{ ref }` بصلاحية `tasks.edit`: عنصر بنفس المشروع، وما هو مربوط مسبقاً (409)؛ و`.../unlink` بيشيله (ويشيله من اليدوي كمان). التدقيق على العنصر باسم الحدث | 404 / 409 |
| R12 | **الأحداث** (`GET /git-events?projectId=&workItemRef=&kind=&q=&page=`، `git.view`): الأحدث أولاً، المشروع إلزامي | 400 |
| R13 | **مؤشر التطوير:** رد العنصر (`GET /work-items/{id}` والقائمة) بيزيد `dev { commits, openPrs, mergedPrs }` لمن يملك `git.view` بمشروعه (وإلا بيغيب). commits = أحداث `push`، وopen = PR بحالة `open`، وmerged = PR بحالة `merged` | — |
| R14 | **المشاريع المؤرشفة** بتستمر تستقبل التسليمات والمزامنة (معلوماتية)، لكن ربط/فصل المستودع ونمط الرمز بيرفضوا 422 (الأرشفة للقراءة فقط، متل 04 R6) | 422 |
| R15 | **الأسرار:** ما بترجع التوكنات ولا الأسرار بأي رد ولا سجل ولا تدقيق، ما عدا الإظهار لمرة وحدة عند الربط (إذا ولّدناه) والتدوير (R1، R3). `hasCredential` فقط بتدل على وجود توكن | — |

## 5. الروابط (`/api/v1`، مجموعتان: «مستودعات Git» و«أحداث Git»)
| الرابط | الصلاحية | الطلب ← الرد | ملاحظات |
|---|---|---|---|
| `GET /projects/{id}/repositories` | `git.view` | ← `[{ id, provider, name, url, defaultBranch, connected, hasCredential, webhookUrl, lastSyncAt, lastSyncError }]` | بدون أسرار |
| `POST /projects/{id}/repositories` | `git.manage` | `{ provider, name, url, defaultBranch, accessToken, webhookSecret? }` ← 201 المستودع + `webhookSecret` (إذا ولّدناه) | R1 |
| `POST /projects/{id}/repositories/{repoId}/disconnect` | `git.manage` | ← المستودع | R2 |
| `POST /projects/{id}/repositories/{repoId}/rotate-secret` | `git.manage` | ← `{ repositoryId, secret }` | R3 |
| `PUT /projects/{id}/ref-pattern` | `git.manage` | `{ refPattern }` ← المشروع | If-Match؛ R4 |
| `POST /webhooks/{provider}/{repoId}` | عام بتوقيع | حمولة المزوّد ← `{ outcome, message, linkedRefs }` | R5–R8 |
| `GET /git/deliveries` | `git.view` | `?projectId=&page&pageSize` ← ترقيم | R9 |
| `POST /git/deliveries/{id}/redeliver` | `git.manage` | ← التسليم | R9 |
| `POST /projects/{id}/git-sync` | `git.sync` | `{ repositoryId }` ← `{ fetched, ingested, linked }` والمستودع | R10 |
| `GET /git-events` | `git.view` | R12 ← ترقيم | |
| `POST /git-events/{id}/link` · `/unlink` | `tasks.edit` | `{ ref }` ← الحدث | R11 |

ورد **المشروع** بيزيد `refPattern`. والعنصر بيزيد `dev`.
الأخطاء problem+json بالعربي بالصيغة المتفق عليها بالجزء 00. الـ enums بنمط kebab (`pull-request`)، وقيم حدث المزوّد الأصلية بتنقرأ من الترويسة.

## 7. سيناريوهات القبول
1. **الربط (R1):** `khaled` (مدير المشروع) بيربط `acme/web` بـ Gitea ← 201 برابط الـ webhook والسرّ المُولَّد مرة وحدة، وما بيرجع التوكن؛ قراءة المستودعات بعدها بدون أسرار؛ ربط الاسم نفسه مرة ثانية ← 409؛ `abdullah` ← 403؛ رابط `http://` أو `https://localhost` أو `https://10.0.0.1` أو بمنفذ أو ببيانات دخول ← 400 بحقل `url`؛ اسم بغير صيغة `owner/repo` ← 400؛ مشروع مؤرشف ← 422.
2. **الاستقبال والتوقيع (R5):** push موقّع صحيح (لكل مزوّد: Gitea وGitHub وGitLab) ← 200 `processed` وبيربط `ERP-104` من الرسالة والفرع؛ توقيع خطأ أو غائب ← 401 ويظهر `rejected`؛ بدون معرّف تسليم أو طابع زمني ← 400؛ طابع قديم أكثر من 5 دقائق أو بعيد بالمستقبل ← 401 `StaleDelivery`؛ تغيير حرف بالجسم بعد التوقيع ← 401؛ مستودع غير موجود ← 404؛ جسم أكبر من 1 ميغابايت ← 413.
3. **عدم التكرار (R6):** إعادة نفس التسليم ← 200 `duplicate` بدون حدث جديد؛ المرفوض ما بيحرق المعرّف (تسليم صحيح بنفس المعرّف بعد رفضه بيمر)؛ إعادة نفس الـ commit بمعرّف تسليم جديد ما بتنشئ حدثاً ثانياً.
4. **الربط التلقائي (R7):** رموز بالرسالة والفرع تنربط، ورمز لعنصر غير موجود أو من مشروع ثاني ما بيتربط؛ نمط مخصّص بيغيّر الالتقاط؛ commits متعددة بتسليم واحد؛ نص أطول من 2000 حرف الرمز بعده ما بيُلتقط.
5. **طلبات السحب (R7/R8):** فتح PR ← حدث `open`، دمجه ← نفس الحدث `merged` (مش حدثاً جديداً) ويحتفظ بالرابط اليدوي؛ حالة العنصر وموافقاته ما تغيّرت؛ حدث GitLab `Merge Request Hook` بيتعامل كـ PR.
6. **الفشل وإعادة المعالجة (R9):** جسم فاسد موقّع ← `failed` بالسجل؛ `redeliver` من `git.manage` ← 422 إذا ما هو فاشل، وإذا انصلح الشرط (مثلاً عنصر انكتب بعد الفشل) بتصير `processed` ويتمسح الجسم؛ ومن غيره 403.
7. **السجل (R9/R12):** `GET /git/deliveries` بدون `projectId` ← 400، ومشروع ما بتشوفه ← 404، وبدون `git.view` ← 403؛ بدون الجسم الخام؛ `GET /git-events` بفلتر `workItemRef` و`kind`.
8. **المزامنة (R10):** بمزوّد وهمي (بالاختبار) بيرجّع 3 commits: أول مزامنة ← `ingested = 3` والروابط، ثانية ← 0؛ مستودع مفصول ← 422؛ فشل المزوّد ← 502 و`lastSyncError`؛ بدون `git.sync` ← 403؛ والتدقيق بيسجّل الأعداد.
9. **التدوير والفصل (R2/R3):** بعد التدوير التوقيع بالسرّ القديم ← 401 والجديد ← 200؛ بعد الفصل التسليم ← 401 والأحداث السابقة باقية؛ تدوير مستودع مفصول ← 422؛ والتدقيق ما فيه أي قيمة سرّ.
10. **نمط الرمز (R4):** نمط بدون مجموعة أو بمجموعتين أو بمرجع خلفي أو بتطلّع أمامي أو أطول من 100 ← 422؛ نمط ما بيلتقط رموز المشروع ← 422؛ نمط صالح بيتخزّن ويظهر بـ `refPattern` ويرفع ETag؛ إعادته فاضياً ← الافتراضي.
11. **الربط اليدوي (R11):** `tasks.edit` بيربط commit بعنصر من نفس المشروع؛ مرّتين ← 409؛ عنصر مشروع ثاني ← 404؛ فك الربط؛ بدون الصلاحية ← 403.
12. **مؤشر التطوير (R13):** `GET /work-items/{id}` بيرجّع `dev` بالأعداد الصحيحة (commits وopenPrs وmergedPrs) لمن معه `git.view`، وبدونه الحقل غايب؛ وبالقائمة كمان.
13. **الأرشفة (R14):** مشروع مؤرشف: التسليم والمزامنة بيمروا، وربط مستودع جديد أو نمط ← 422.
14. **الأسرار (R15):** قراءة المستودع والتدقيق وأي رد خطأ ما فيهم توكن ولا سرّ؛ التشفير بالقاعدة (العمود ما بيطابق القيمة).
15. كل تعديل بيظهر بـ `audit_log` مع `user_id`؛ `dotnet test` ناجح؛ الروابط ظاهرة بـ `/docs`؛ و`docs/http/07-git-integration.http` فيه مثال لكل رابط (بما فيه توقيع تجريبي بـ openssl).

## 8. قرارات
**حسمها صاحب المشروع:** الجزء 07 بعد الموافقات (الخارطة)، وتواقيع HMAC وعدم التكرار وحماية إعادة الإرسال من الـ SRS.

**أخدتها أنا (صحّحني إذا لازم):**
- **تشفير الأسرار بـ AES-GCM بمفتاح من الإعداد** (`Git:SecretKey`) بدل ما نحفظها نصاً. الـ webhook بحاجة للسرّ الأصلي (HMAC) والتوكن لازم نرسله، فما بنقدر نخزّن Hash. بالإنتاج لازم المفتاح وإلا ما يقلع؛ ولأن Data Protection بتفقد المفاتيح مع إعادة إنشاء الحاوية اخترت مفتاحاً صريحاً.
- **نمط الرمز بمحرّك `NonBacktracking` ومهلة** بدل نقل فحص ReDoS البنيوي (`isCatastrophic`) من الواجهة؛ المحرّك ما بيدعم المراجع الخلفية والتطلّع فبنرفضها بالفحص، وغيرها آمن بتصميمه.
- **المزامنة بتجيب آخر 50 commit من الفرع الافتراضي فقط** (مش كل الفروع ولا الـ PR). كفاية للتعويض عن webhook فاتتنا؛ والباقي بيجي بالـ webhook. تنفيذ المزوّدات الثلاثة (واجهات Gitea وGitHub وGitLab) بـ HTTP حقيقي، وبالاختبارات بنبدّلها بمزوّد وهمي، لأن ما في خادم Git حقيقي.
- **ما في تسجيل تلقائي للـ webhook عند المزوّد:** المستخدم بيلصق الرابط والسرّ هناك (متل الواجهة).
- **الأرشفة بتبقى بتستقبل** التسليمات والمزامنة لأنها معلومات، وبتمنع تغيير الربط والإعداد.
- **السر المُولَّد بيرجع مرة وحدة عند الربط** (الواجهة الحالية ما بتعرضه، لكن بدونه المستخدم ما يقدر يضبط الـ webhook).
- **لا إشعارات هلق:** إشعار «دُمج PR مرتبط» للمكلّفين بالجزء 08.
- **لا حدّ معدّل مخصّص للـ webhook** هلق (التوقيع إجباري قبل أي معالجة)؛ إذا بدك حدّاً لكل مستودع قلّي.

## 9. نقاط ربط للأجزاء الجاية (مش ضمن هالجزء)
| الجزء | بيضيف |
|---|---|
| 08 النشاط والتدقيق | إشعار دمج PR، وأحداث Git بشاشة نشاط المشروع/العنصر، وتدقيق أحداث الأمان للتسليمات المرفوضة |
| 09 اللوحات والإعدادات | نشاط Git بلوحة القيادة، وإعدادات عامة (نافذة الإعادة، حجم الجسم) |

## 10. مش ضمن الجزء
الكتابة على مزوّد Git (إنشاء فروع أو تعليق على PR أو إغلاقه)، تسجيل الـ webhook تلقائياً، OAuth للمزوّدات، مزامنة الفروع والـ PR بالتفصيل، الإشعارات (08)، اللوحات (09).

## 11. تعديلات أثناء التنفيذ
1. **`webhookUrl`** مسار نسبي (`/api/v1/webhooks/{provider}/{id}`)؛ الواجهة بتحط مضيفها قدّامه.
2. **المزامنة** بصلاحية `git.sync` (مدير المشروع عنده `git.sync` بدون `git.manage`) والرد `{ fetched, ingested, linkedRefs, repository }` (`linkedRefs` بدل `linked`). مزامنة المزوّد بتنقل `lastSyncAt` وآخر خطأ؛ ما في سجل تدقيق لعدّاد المزامنة غير هالحقول.
3. **مؤشر `dev`** بيتحسب بالذاكرة من أحداث المشروع (بلا جدول مجمّع)، وبيظهر فقط لمن عنده `git.view` بالمشروع (القارئ ما بيشوفه).
4. **ثلاث مجموعات OpenAPI** بدل اثنتين: «مستودعات Git» و«ويب هوك Git» و«أحداث Git».
5. **رمز الخطأ للجسم الكبير:** الاستقبال بيرجّع 413 مباشرة من الواجهة (قبل قراءة كل الجسم)، بدون تسليم مسجّل.
6. **المفتاح:** `Git:SecretKey` (base64 لـ 32 بايت) إلزامي وبيفشل التشغيل بدونه؛ مفتاح التطوير بـ `appsettings.Development.json` والاختبار بـ `ApiFactory`، وبالإنتاج من `Git__SecretKey`.
7. **الاختبارات:** مزوّد Git وهمي (`FakeGitRemote`) بدل الاتصال الحقيقي؛ تواقيع المزوّدين الثلاثة بتتبنى بالاختبار بشكل مستقل عن الكود.
