# ERP101 Backend: خط إنتاج الأجزاء

> كيف نبني النظام: جزء جزء، وكل جزء يمشي نفس المراحل الثابتة.
> شغلنا هو الـ backend فقط. ما منربط مع الواجهة، **اللي منسلّمه هو روابط API موثّقة**.
> الواجهة (`../erp101/frontend`) مرجع للفهم فقط: `docs/architecture/ERD.dbml`، `WORKFLOW.md`، `SYSTEM-DESIGN.md`، والكود.

## 1. المراحل الثابتة لكل جزء

```
 0. مواصفة ──✋──► 1. المجال ─► 2. التخزين ─► 3. التطبيق ─► 4. الـ API ─► 5. تسليم ──✋
```

| # | المرحلة | الناتج | معيار الانتهاء |
|---|---|---|---|
| 0 | **تحليل ومواصفة** | `docs/modules/NN-<part>.md`: الجداول، القواعد، الصلاحيات، الروابط مع الطلب والرد، سيناريوهات القبول | ✋ موافقة صاحب المشروع |
| 1 | **المجال** | الكيانات وقواعدها في `Erp101.Domain` + اختبارات وحدة | الاختبارات ناجحة |
| 2 | **التخزين** | إعداد EF Core للجداول، migration، قيود وفهارس، بيانات أولية (seed) | الـ migration بيطبّق على قاعدة فاضية |
| 3 | **التطبيق** | أوامر واستعلامات (Mediator)، FluentValidation، الصلاحية لكل أمر. **كل عملية بمجلد لحالها** تحت `Commands/` أو `Queries/` (القسم 4) | اختبارات الـ handlers واختبارات البنية ناجحة |
| 4 | **الـ API** | رابط واحد بكل مجلد، أخطاء problem+json بالعربي، ETag/If-Match، ترقيم + اختبارات تكامل على Postgres حقيقي | كل سيناريوهات المواصفة بتنجح |
| 5 | **التسليم** | الروابط ظاهرة في صفحة التوثيق (OpenAPI)، ملف `docs/http/NN-<part>.http` فيه مثال لكل رابط، تحديث التوثيق، commit | ✋ موافقة صاحب المشروع، والروابط جاهزة للتسليم |

### قواعد بتنطبق على كل جزء
- **ما في كود قبل الموافقة على المواصفة.** إذا تغيّر شي مهم خلال المراحل 1–4، منرجع للمواصفة ومنعدّلها قبل ما نكمّل.
- المراحل 1 لـ 4 بتمشي مرة وحدة بدون توقف للمراجعة، بس كل مرحلة لازم توصل لمعيار انتهائها قبل اللي بعدها.
- الجزء ما بيعتبر خلصان إلا إذا `dotnet test` ناجح بالكامل، و`docker compose up` بيشغّل الـ API، والروابط بتشتغل من صفحة التوثيق ومن ملف `.http`.
- ترحيل بيانات localStorage القديمة **مش من شغلنا**. بداله كل جزء إله بيانات أولية للتجربة.

## 2. ترتيب الأجزاء

الترتيب حسب الاعتماديات: كل جزء بيعتمد بس على اللي قبله.

| # | الجزء | الجداول / المحتوى | بيعتمد على |
|---|---|---|---|
| 00 | **الأساس** | Docker، سجل التدقيق، التزامن، صيغة الأخطاء، بنية الاختبارات، صفحة التوثيق | — |
| 01 | **الهيكل التنظيمي + الدخول** | الأقسام، الموظفين، الأدوار، الصلاحيات العشرين، Identity/JWT، Redis للصلاحيات | 00 |
| 02 | البرامج والمشاريع | CompanyProfile، Program، Project، ProjectModel، SerialUnit | 01 |
| 03 | شجرة المنتج (BOM) | BomNode، القرار (تصنيع/شراء)، الكميات | 02 |
| 04 | الإنتاج | محطات العمل، عمليات المسار، التقدم، الجودة | 01، 03 |
| 05 | المستودعات | المواد، المواقع، الحركات (FIFO/متوسط)، الطلبات | 01، 02 |
| 06 | المشتريات | الموردين، طلب الشراء بمراحله العشر، العروض، MCDM | 03، 05 |
| 07 | المهام والمحادثة | WorkTask، الرسائل، القراءة | 01 |
| 08 | الحقول المخصصة | تعريف الحقول، قيم jsonb على 5 كيانات | الكيانات المعنية |
| 09 | الملفات والتحديث الفوري | MinIO، SignalR | حسب الحاجة |

جزء الأساس (00) ما إله جداول عمل ولا seed، فمراحله 1–4 بتختصر على اللي بيلزمه.

## 4. بنية الكود لكل جزء (قاعدة ثابتة)

كل عملية (إنشاء، تعديل، حذف، قراءة…) إلها **مجلد لحالها**، والأوامر مفصولة عن الاستعلامات، و**كل ملف فيه نوع واحد بس**.
وطبقة الـ API ماشية على نفس التقسيم: رابط واحد بكل مجلد. المثال المرجعي هو الأدوار بالجزء 01:

```
Erp101.Application/Features/People/Roles/
├── Commands/
│   ├── CreateRole/          CreateRoleCommand.cs · CreateRoleCommandValidator.cs · CreateRoleCommandHandler.cs
│   ├── UpdateRole/          UpdateRoleCommand.cs · UpdateRoleCommandValidator.cs · UpdateRoleCommandHandler.cs
│   ├── SetRolePermissions/  …
│   └── DeleteRole/          DeleteRoleCommand.cs · DeleteRoleCommandHandler.cs   (بدون validator لأنه ما في حقول)
├── Queries/
│   ├── GetRoles/            GetRolesQuery.cs · GetRolesQueryHandler.cs · RoleListItem.cs
│   └── GetRoleById/         GetRoleByIdQuery.cs · GetRoleByIdQueryHandler.cs
└── Common/                  RoleResponse.cs · RoleMapping.cs · RoleRules.cs   (المشترك بين أكتر من عملية)

Erp101.Api/Endpoints/People/Roles/
├── CreateRole/              CreateRoleEndpoint.cs · CreateRoleRequest.cs
├── GetRoles/                GetRolesEndpoint.cs
└── …
```

- **الأسماء:** المجلد هو اسم العملية (`CreateRole`)، وجوّاه `CreateRoleCommand` و`CreateRoleCommandHandler` و`CreateRoleEndpoint`. الاستعلامات بتبلّش بـ `Get`.
- **الرد** اللي بيستعمله استعلام واحد بيقعد جنبه بمجلده. المشترك بين أكتر من عملية بيروح على `Common/`.
- **الـ endpoint ما فيه منطق:** بيقرأ الطلب، وبيبعت الأمر لـ Mediator، وبيرجّع الرد. المنطق بالـ handler والكيان.
- **مفروضة باختبار:** `tests/Erp101.ArchitectureTests/FeatureStructureTests.cs` بيفشّل البناء إذا انكسرت أي قاعدة من هدول.
